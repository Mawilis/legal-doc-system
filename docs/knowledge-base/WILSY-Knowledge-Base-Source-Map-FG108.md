# WILSY OS Knowledge Base Source Map — FG108

## Purpose

Wilsy OS Knowledge Base is the global training, guide, playbook, and product-memory layer for permissioned users.

The goal is not to store static PDFs in the repository only. The goal is to make every important Wilsy OS feature, stable tag, algorithm, workflow, and operating doctrine available as searchable, printable, permissioned user guidance.

## Global access doctrine

Founder Dashboard must not be the only access point.

The Knowledge Base must be global and permissioned:

1. Founder Dashboard gets admin and publishing controls.
2. Tenant users get read, search, print, and download access according to role.
3. The global authenticated shell should expose a Knowledge Base launcher.
4. Future workspace help can open the relevant playbook without blocking the user's work.
5. Generated PDFs are saved and reopened later; users should not need to call backend generation to read them.

## Why this beats competitors

Common SaaS patterns split learning across help centers, static docs, walkthrough prompts, and workspace search.

Wilsy OS must combine them into one governed operating layer:

    feature/tag/algorithm
    -> playbook markdown
    -> governed PDF export
    -> manifest entry
    -> permissioned Knowledge Base Vault
    -> global search/read/print access
    -> future AI/operator retrieval
