## 1. Architectural Pillars
The engine operates on a four-tier architecture to ensure enterprise-grade stability:

### I. Cognitive Layer (Model Abstraction)
*   **Multi-Model Router:** Unified interface to switch between local Ollama instances (for privacy) and high-compute remote APIs.
*   **Context Injection:** Real-time state injection from the .wilsy_graph.json database.

### II. Governance & Security (Guardrails)
*   **Secret Guard:** Static analysis suite preventing credential leakage during synthesis.
*   **Logic Auditor:** Enforces the "Biblical" standard—ensuring all generated code is optimized, modular, and future-proof.

### III. Operational Pipeline
*   **Forensics:** AI-driven analysis of codebase drift or vulnerability patterns.
*   **Automated Patching:** Self-healing workflows triggered by Sentinel integrity failures.
*   **Verification:** AI-native unit test generation and recursive proof-checking against Knowledge Graph dependencies.

## 2. The Lifecycle Workflow
The AI Engine strictly adheres to the Generate-Verify-Commit protocol:

1.  **Ingestion:** Accept user intent via CLI.
2.  **Contextualization:** Query the Sentinel/Graph for relevant structural dependencies.
3.  **Synthesis:** Generate solution/patch (Model agnostic).
4.  **Verification:** Pass through the Logic Auditor and internal build tests.
5.  **Commit:** Atomic write to filesystem; update Knowledge Graph; inform Sentinel.

## 3. Operational Commands (CLI)
The Wilsy AI Engine is invoked via the wilsy-engine binary. This ensures absolute version control, auditability, and integrity.

# 1. Synthesize the logic
wilsy-engine synth "Create PayrollDeduction module with SHA-256 validation" 

# 2. Audit against Biblical coding standards
wilsy-engine audit ./tools/payroll/deduction.py

# 3. Verify against the Sentinel Cryptographic Database
wilsy-engine verify --strict
