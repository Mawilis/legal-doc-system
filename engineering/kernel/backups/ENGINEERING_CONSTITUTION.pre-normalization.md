INSTITUTIONAL ENGINEERING LAWS

-------------------------------------------------------------------------------

LAW EK-001

Repository Evidence First

Purpose

The Engineering Kernel recognizes repository evidence as the highest authority for
engineering decisions. Repository evidence ensures that engineering work is
verifiable, reproducible, and independent of assumptions or undocumented claims.

Constitutional Rule

No engineering claim possesses institutional authority until it is supported by
verifiable repository evidence.

Engineering Rationale

Repository evidence protects Wilsy OS from architectural drift, undocumented
changes, duplicated implementations, and unverifiable engineering decisions.
Evidence creates a permanent institutional record that future engineers and
automation systems can trust.

Repository Evidence Requirements

Every engineering claim shall be supported by one or more of the following:

• Repository file inspection
• Git history
• Git diff
• Repository tree
• File metadata
• Build output
• Guard output
• Test results
• Runtime verification
• Measured execution evidence

Claims of completion, implementation plans, AI reasoning, generated responses,
task status messages, or undocumented observations shall never be accepted as
repository evidence.

Only independently verifiable repository artifacts possess institutional
authority.

Engineering Obligations

Every engineer, automation workflow, AI system, and Engineering Kernel module
shall obtain repository evidence before proposing, approving, or implementing
repository mutations.

Violation

Engineering work performed without repository evidence shall be considered
unverified and shall not be accepted as institutional knowledge.

Compliance Requirements

Every Engineering Packet shall include a Repository Evidence section before any
implementation or approval activity.

Future Compatibility

This law applies equally to human engineers, AI systems, autonomous engineering
agents, and future Wilsy OS capabilities.
